# 作品集体验分析报告（v1 · 2026-11-16）

> 这份报告分两部分：**上线前**的逐屏体验走查（基于当前代码与真实渲染），以及**数据上线后**怎么用看板读体验、先改什么、怎么验证。
> 文中「示例数据」全部来自 `analytics/tools/generate.mjs` 的合成数据，**不是真实访问量**，只用于演示口径与看板；真实性能数字来自本机 Chrome 冷缓存实测。

---

## 1. 一句话结论

作品集的信息结构和视觉完成度已经很高，真正的体验损耗集中在三处：**作品入口太依赖「横向流」这一种交互、长案例缺少阅读引导、简历下载路径偏深**；同时**首屏封面图片偏重**（桌面首载 2.9 MB / 移动 2.1 MB）。这四点都能用这次新增的埋点直接量化，并按下面 P0→P2 的顺序验证。

先做四件事，收益最大：

1. 首屏封面响应式化，只预加载第一张（桌面首屏 ≤900 KB，移动 ≤500 KB）。
2. 首页横向流加「还有更多」的可见提示（露半张卡 + 移动端滑动提示），并在首次访问时给一次手势提示。
3. 作品查看器第 1 页加「向下滚动 / ↑↓ 翻页」引导，并明确显示页码（当前已有 01/25，但缺少操作提示）。
4. 把「下载简历」从弹窗底部提升为稳定可见的 CTA（尤其移动端），并在 THANK 页补一个下载入口。

## 2. 怎么衡量体验：指标与建议目标

看板已经按这套口径出数（定义见 `analytics/README.md §2`）。

| 体验问题 | 指标 | 建议目标（真实流量） | 低于目标的含义 |
|---|---|---|---|
| 首页有没有被看到 | 首页曝光会话率 = `home_sessions / sessions` | ≥ 85% | 大量深链直达作品页（需结合来源拆开看） |
| 封面有没有被看到 | 封面曝光覆盖率 = `impression_sessions / sessions` | ≥ 70% | 首屏露出不足 / 用户没横向探索 |
| 封面能不能让人点 | 点击会话率 = 有点击会话 / 曝光会话 | ≥ 12% | 封面文案、信息层级或 CTA 不足 |
| 点开后能不能留住 | 首屏跳出率 = 只看第 1 页就退出 / 打开 | ≤ 35% | 第一页像「封面墙」、缺少阅读引导 |
| 内容能不能被读完 | 平均浏览深度、看到末页率 | 深度 ≥ 35%；短案例完成 ≥ 20%，长案例 ≥ 8% | 页数过长、节奏缺少阶段性结论 |
| 有没有人了解你 | 关于我打开率 | ≥ 12% | 入口权重低 / 不知道点哪里 |
| 简历有没有被拿走 | 下载 / 关于我打开 | ≥ 20% | 下载按钮不显眼、路径深 |
| 性能 | LCP p75 / CLS p75 / INP p75 / TTFB p75 | ≤ 2.5s / ≤ 0.1 / ≤ 200ms / ≤ 800ms | 首屏图过重或加载策略问题 |
| 首页第一眼 | 无交互会话率 | ≤ 15% | 首屏没讲清「是谁、做什么、看哪个」 |

> 阈值是起点，不是 KPI 考核。个人作品集流量小，先看**趋势和逐页流失位置**，不要被单日波动带跑。

## 3. 上线前逐屏走查（真实渲染 + 代码）

### 3.1 首页

**现状（1440×900 实测）**

- 顶部：品牌、TEL/邮箱、「关于我」；左侧大标题，右侧个人信息（可点击打开关于我）。
- 中部：三组经历的横向作品流，6 张封面；1440 宽下卡片约 259×417，首屏可见 4 张抖音封面 + 京东封面的一部分，金山词霸在屏幕外。
- 卡片信息：左上项目名 + 页数，底部序号 + 类型；hover 停留 150ms 后按 16:9 中心展开，其余卡片压暗并被推开。
- 底部有 `SCROLL / DRAG TO EXPLORE` 文案，但在页面最下方。

**体验判断**

| 观察 | 影响 | 证据 |
|---|---|---|
| 横向流是唯一作品入口，但「可横向拖动」在首屏没有视觉提示 | 部分用户不知道还能往右看，金山词霸/后续项目曝光天然偏低 | 首屏 5 张卡、第 6 张完全在视口外；页脚提示在折叠线以下 |
| 移动端没有 hover，卡片信息只显示名称与页数，无「点击查看」文案 | 移动端点击率/打开率可能明显低于桌面 | 390 宽下卡片约 290px，首屏仅 1.3 张卡 |
| hover 展开 150ms 延迟是为了防误触，但展开前没有任何「可点」反馈（除 cursor） | 桌面用户可能只看到静态封面 | `.stream-project` hover 仅改变宽度/阴影，无 CTA |
| 卡片底部信息（序号 + PLATFORM · WEB）对比度低 | 辅助信息可读性弱 | 小号文字使用低对比灰色 |

**可埋点验证**：`card_impression`（曝光覆盖）、`card_click`（点击会话率）、`stream_scroll`（横向探索 25/50/75%）、`home_exit.max_progress`；按设备拆 `devices[].bounce_rate`。

### 3.2 作品查看器

**现状**

- 从首页点卡片直接进入查看器（中间的项目导航页只在禁用项目/直接路由时兜底），首屏是封面即第 1 页。
- 桌面右侧竖排缩略图，竖屏底部横排；页面计数 01/25；滚轮/键盘/滑动/点击缩略图翻页；右上角全屏。
- 最后一页内容页与 THANK 页会滑出「其他项目」面板；THANK 页有电话/邮箱链接。
- 加载时超过 220ms 才出现模糊遮罩 + spinner，避免快缓存闪烁。

**体验判断**

| 观察 | 影响 | 证据 |
|---|---|---|
| 进入后第一眼是封面，没有「向下滚动」提示 | 用户可能以为这是一张静态图，直接返回（首屏跳出） | 首屏交互提示只存在于缩略图栏的小字「滚动或点击缩略图浏览」，视觉权重低 |
| 长案例（抖音创作服务平台 24 页、京东数坊 37 页）没有章节感/进度感 | 完成率低、中段流失集中 | 只有页码 01/25；没有章节标题或进度条 |
| 第 1 页（封面）与第 2 页风格可能跳变 | 第 1→2 页流失通常是全程最大 | 看板逐页到达率第 1→2 页的落差可直接验证 |
| 全屏下「左键下一页 / 右键上一页」没有提示 | 该手势无法被发现 | 仅代码实现，无 UI 提示 |
| THANK 页有联系方式，但没有简历下载 | 最后一个高意向触点少了转化动作 | `.thank-slide` 只有 TEL/EMAIL |

**可埋点验证**：`viewer_open`、`viewer_slide`（逐页）、`viewer_exit`（首屏跳出、深度、完成）、`fullscreen_toggle`、`stack_step`（叠层页是否被继续翻）、`video_play`。

### 3.3 关于我 & 简历下载

**现状**

- 两个入口：顶栏「关于我」按钮、首页右上角个人信息块；打开为 1080px 两栏弹窗（≤860px 单栏）。
- 左栏：ABOUT/关于我、头像、姓名、角色、学历/现职、经验/方向/现职/状态、TEL/微信/邮箱、**最底部下载 PDF 简历**。
- 右栏：自我介绍 + 可折叠「能力亮点 3 项」+ 三段项目经历（后两段带折叠职责）。
- 两栏内部滚动；原生滚动条隐藏，改用 hover 才淡入的自绘滚动条；Esc/遮罩/关闭按钮可退出。

**体验判断**

| 观察 | 影响 | 证据 |
|---|---|---|
| 下载按钮位于左栏最底部，桌面需要滚到左栏底部才看到 | 关于我 → 下载的转化被削弱 | `.about-download` 在 `.about-side` 末尾 |
| 移动端单栏时，下载排在个人信息/联系方式之后、右栏之前 | 移动端需先滚过约一屏 | `≤860px` 单栏顺序：左栏 → 右栏 |
| 隐藏原生滚动条 + 自绘滚动条只在 `:hover` 淡入 | 触屏设备可能完全看不到「可滚动」提示 | `.contact-card:hover .about-col[data-scrollable]` 才显示 |
| 头部 TEL/EMAIL 一直可见，「关于我」按钮视觉权重一般 | 用户可能直接复制邮箱，不进弹窗 | 顶栏按钮与正文同级颜色 |
| 下载后没有成功反馈（浏览器直接保存） | 用户不确定是否开始下载 | 点击后无 toast |

**可埋点验证**：`about_open`（两入口来源）、`about_close`（停留、左右栏滚动深度）、`about_fold`（能力亮点/职责是否展开）、`resume_download`（下载/打开转化）、`contact_click`（tel/email 点击）。

### 3.4 性能（本机冷缓存实测）

| 视口 | 首载传输 | 图片传输 | 首屏加载图片数 | 备注 |
|---|---|---|---|---|
| 1440×900 | 2,909 KB | 2,609 KB | 10（6 张封面全加载） | 单张封面 364–508 KB |
| 390×844 | 2,088 KB | 1,787 KB | 8（4 张封面） | lazy 生效不完整，仍有 4 张封面下载 |
| 1920×1080 | 2,909 KB | 2,609 KB | 10 | 同上 |

- 封面总量约 2.5 MB；`loading="lazy"` 在横向流里挡不住离屏封面被提前加载（浏览器按距离阈值加载），这是首屏最大的性能负债。
- 内页已做 960/1280/1920/2560 WebP 变体 + 预加载 + 占位/加载遮罩，查看器内部表现是健康的；问题集中在**首页封面**。
- 本机 LCP 124–184ms 只说明逻辑没有阻塞；真实 4G 下 2.6 MB 图片预计把 LCP 推到 3–5s，看板 `vitals.lcp_p75` 会用真实用户数据验证。

**建议目标**：首屏图片 ≤ 800 KB（桌面）/ 500 KB（移动），LCP p75 ≤ 2.5s；封面保留现有 3200×1800 母版，补 640/960/1280 三档 `srcset` 与 AVIF/WebP。

## 5. 上线后 30 天：先改什么、怎么验证

### 第 0 步：把数据跑通（半天）

1. 按 `analytics/README.md §4` 部署 Worker + D1，绑定自定义域名（国内可达性）。
2. 在 `index.html` 填 endpoint，发布 GitHub Pages。
3. 自己用手机/桌面各走一遍：首页 → 点作品 → 翻 3 页 → 打开关于我 → 下载简历。
4. 看板核对：`sessions` 有数、`page_view` 与 `home_view` 对得上、`viewer_exit` 有值、`resume_download` 有 1 条、无错误。
5. 给自己发几个不同渠道的链接并带 UTM，验证来源拆分。

### 第 1 周：只收基线，不改版（除非 P0 是明显 bug）

- 每天看一次：会话、曝光会话率、点击会话率、首屏跳出、关于我打开率、下载率。
- 记录 7 天基线（中位数比均值更稳）；确认没有异常流量/重复事件/错误。
- 用「逐页到达图」找出每个作品的最大流失页，截图存档，作为改版前基线。

### P0（第 2 周，预计 2–3 天工作量）

| # | 改动 | 为什么 | 预期指标 | 看板验证 |
|---|---|---|---|---|
| P0-1 | 首页封面响应式：`srcset` 640/960/1280/1920 + AVIF/WebP，首张 `fetchpriority=high`，其余真正懒加载（改 IntersectionObserver 或缩小 `loading=lazy` 的提前量） | 首屏 2.6 MB 图片是最大性能负债 | 首屏图片 ≤800 KB；LCP p75 -30~50%；首屏跳出 -3~8pt | `vitals.lcp_p75`、`load.avg_image_kb`、`viewer_bounce_rate` |
| P0-2 | 横向流发现性：右侧露半张卡 + 移动端「左右滑动」提示 + 首访 3s 手势提示（可关闭，记忆 7 天）；页脚提示上移 | 金山词霸/后续项目曝光偏低 | 封面曝光覆盖率 +10~20pt；`stream_scroll` 50% 会话 +8pt | `impression_sessions / sessions`、`home.scroll_buckets`、`card_impression` 分布 |
| P0-3 | 查看器首访引导：「向下滚动 / ↑↓ 翻页」浮层 2.5s；每页右下角页码更明显；桌面显示「下一页」箭头 | 第 1 页像静态封面，直接返回 | 首屏跳出 -8~15pt；平均深度 +5pt | `viewer_bounce_rate`、`viewer_avg_depth_pct`、逐页到达第 1→2 页 |
| P0-4 | 简历 CTA 前置：关于我左栏顶部固定「下载 PDF 简历」；移动端单栏把下载放到个人信息之后、经历之前；THANK 页加下载按钮；下载后 2s toast | 下载入口深、无反馈 | 下载/关于我 +5~10pt；下载会话率 +2~4pt | `about.per_open`、`resume_download_sessions`、`about_close.main_scroll` |

> 一次只改一个 P0，间隔至少 3–5 天再上下一个；否则无法归因。流量小可以用「改前 7 天 vs 改后 7 天」比较，并避开周末/节假日的结构差异。

### P1（第 3–4 周）

- **长案例章节化**：给 24/37 页的案例加章节导航（或每 5 页一个「阶段结论」页）；目标完成率翻倍、后半程到达率抬升。验证：`slide_reach` 曲线变平、`viewer_exit.max_percent` 分布右移。
- **封面文案升级**：项目名 + 一句「做了什么 + 结果数字」；A/B 不可行时用前后 7 天点击会话率对比。验证：`card_click / card_impression`、各项目 `ctr`。
- **移动端缩略图折叠**：竖屏底部缩略图条改成可展开，给作品更大显示面积；目标手机跳出下降。验证：`devices.mobile.bounce_rate`、`viewer_avg_depth_pct`。
- **末页转化**：THANK 页加「下载简历 / 打开关于我」两个 CTA，承接高意向读完的人。验证：`about_open` 的 `screen=viewer` 占比、`resume_download` 来源。

### P2（持续）

- 图片走 CDN/AVIF、字体子集化、预连接；给看板加周报邮件（Cloudflare Cron + 邮件 API）。
- 分享渠道加 UTM，按来源看「点击率 / 深度」，决定把作品集投到哪里。
- 若浏览量上来，再考虑把聚合改成 SQL 预聚合（当前 3 万行内 JS 聚合足够）。

## 6. 每周 10 分钟复盘清单

1. 看板选「最近 7 天」，先看 4 个头部指标：曝光会话率、点击会话率、首屏跳出、下载/关于我。
2. 打开「作品内浏览与跳出」：切换每个作品，找最大流失页；记下页码。
3. 「关于我 & 简历」：打开率、停留、下载转化；若打开率高但下载低，改 CTA；若打开率低，改入口。
4. 「访问结构」：手机/桌面跳出差、来源变化、LCP p75、错误列表。
5. 「体验诊断」：高优项逐条处理；处理完在下次复盘看对应指标是否变化。
6. 记录一周结论（一句话 + 一个要改的点），避免同时改太多。

**上线后 7 天 / 14 天 / 30 天各做一次**：
- 7 天：确认数据质量与基线，不改版。
- 14 天：P0 改版后第一轮对比（同设备、同来源结构下比）。
- 30 天：看 P1 是否值得做；决定是否继续投入（若 30 天 < 50 会话，结论仅供参考）。

## 7. 数据局限与偏差（看数时请记住）

1. **下载 ≠ 成功保存**：`resume_download` 是点击意图；浏览器是否落盘、是否打开 PDF 无法可靠区分。
2. **DNT/GPC 用户不上报**：隐私优先，实际会话数会略低于真实访问。
3. **广告拦截/网络失败**：上报失败会重试 3 次并落本地队列，但极端情况下仍可能丢事件；看板 `truncated` 与 `errors` 可用于判断数据质量。
4. **匿名去重**：清 localStorage / 换设备 / 无痕会算新访客；无法跨设备识别。
5. **会话 30 分钟上限**：长时间停留会被切成多个会话，平均时长会偏低（活跃时长已扣除隐藏标签页）。
6. **曝光门槛偏严**：≥50% 可见 500ms 才算曝光，快速划过不计；曝光数不是「渲染数」。
7. **深链**：直接打开作品页会计入作品打开但不计首页曝光，因此「打开/点击」可能 >100%，看板已按此解释。
8. **页数分母**：查看器总页数含 THANK；「完成率」按最后一个内容页算，两者不要混。
9. **合成示例数据**：只用于看板演示和口径验证，不能作为真实结论或对外引用。
10. **没有录屏/热图**：本方案重指标与漏斗，不采集鼠标轨迹；需要定性观察时可临时用本地录屏或第三方工具，注意隐私与告知。

## 8. 结论

作品集已经具备「被点开、被读完、被联系」的完整结构，当前最值得投入的不是再加内容，而是**降低发现成本**（横向流提示）、**降低第一页的放弃率**（滚动引导）、**缩短简历路径**（CTA 前置）和**减重首屏**（封面响应式）。这四件事都能被这次新增的埋点直接量化：曝光 → 点击 → 打开 → 逐页 → 关于我 → 下载，每一跳都有会话级分母和来源/设备拆分。

先按第 0 步把数据跑通、收 7 天基线，再按 P0 顺序一次改一个；30 天后回看，应该能看到「曝光覆盖 ↑、首屏跳出 ↓、下载/关于我 ↑、LCP ↓」四条曲线中至少三条明显改善。
